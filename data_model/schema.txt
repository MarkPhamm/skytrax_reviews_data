Skytrax review data models
==========================

Four independent star schemas, one per review subject. Each is built by dbt on
DuckDB and exported as CSVs into its own directory under data/:

    data/airlines_reviews_model/    airline (flight) reviews
    data/airport_reviews_model/     airport reviews
    data/lounge_reviews_model/      airport lounge reviews
    data/seat_reviews_model/        aircraft seat reviews

Each model is self-contained - it carries its own copy of every dimension it
needs, so a directory can be shipped and queried on its own. Where the same
dimension appears in more than one model (dim_airline, dim_aircraft,
dim_customer) the definition and the keys are identical, so the models can also
be unioned or joined across subjects.

Key conventions
---------------
* Fact primary key is review_id, carried straight through from the source.
  Fact row counts are slightly below the raw CSV row counts: the source
  re-issues review_id on re-ingest, and staging removes those duplicate
  scrapes (see the data quality section of README.md).
* Dimensions with a stable source id (airline_id, airport_id) use it as the PK.
* Dimensions derived from free text use a deterministic surrogate hash of their
  natural key (dbt_utils.generate_surrogate_key).
* dim_date is keyed on the date itself; its range is derived from the dates
  actually present in that model.
* Text attributes that carry a dimension key are coalesced to 'unknown' rather
  than left null, so every fact row resolves to a dimension row.
* Ratings are 1-5 and nullable - reviewers only score the categories they care
  about. average_rating is the mean of the categories actually scored.
* rating_band: unknown (no ratings), bad (<2), medium (<4), good (>=4).


data/airlines_reviews_model/
============================

fct_airline_review
------------------
review_id PK bigint
airline_id bigint FK >- dim_airline.airline_id
customer_id string FK >- dim_customer.customer_id
date_submitted_id date FK >- dim_date.date_id
date_flown_id NULL date FK >- dim_date.date_id
origin_location_id string FK >- dim_location.location_id
destination_location_id string FK >- dim_location.location_id
transit_location_id string FK >- dim_location.location_id
aircraft_id string FK >- dim_aircraft.aircraft_id
is_verified bool
seat_type string
type_of_traveller string
has_layover bool
seat_comfort NULL int
cabin_staff_service NULL int
food_and_beverages NULL int
inflight_entertainment NULL int
ground_service NULL int
wifi_and_connectivity NULL int
value_for_money NULL int
recommended bool
average_rating NULL float
rating_band string
review_text string
source_updated_at timestamp
dbt_loaded_at timestamp

dim_airline
-----------
airline_id PK bigint
airline_name string
airline_name_cleaned string

dim_customer
------------
customer_id PK string
customer_name string
nationality string
number_of_reviews int
first_review_date date
latest_review_date date

dim_location
------------
location_id PK string
city string
airport string          -- IATA code

dim_aircraft
------------
aircraft_id PK string
aircraft_model string
aircraft_manufacturer string
seat_capacity NULL int

dim_date
--------
date_id PK date
day_of_week int         -- 1 = Monday .. 7 = Sunday
day_of_week_name string
cal_week_start_date date
day_of_month int
cal_month int
cal_mon_name string
cal_mon_name_short string
cal_quarter int
cal_quarter_name string
cal_year int
is_weekend bool
fin_year int            -- fiscal year starts 1 July
fin_period int
fin_quarter int
fin_week int
fin_period_name string
fin_quarter_name string
fin_week_name string
