# Four star schemas, one fact per review subject, sharing one conformed
# dimension bus. Built by dbt on DuckDB and exported as CSVs.
#
#   data/conformed/                 dim_airline, dim_customer, dim_aircraft, dim_date
#   data/airlines_reviews_model/    airline (flight) reviews
#   data/airport_reviews_model/     airport reviews
#   data/lounge_reviews_model/      airport lounge reviews
#   data/seat_reviews_model/        aircraft seat reviews
#
# Dimensions used by more than one fact are built once. A subject folder keeps
# only its fact and the dimensions that fact alone uses.
#
# Fact primary key is review_id, carried straight through from the source.
# Dimensions with a stable source id (airline_id, airport_id) use it as the PK.
# Dimensions derived from free text use a deterministic surrogate hash.
# dim_date is keyed on the date itself. Its range is the union of every date
# column across all four subjects.
# dim_customer is one row per (customer_name, nationality). Review counts and
# first/latest dates span all four subjects; a subject the customer never
# reviewed is 0, not a missing row.
# Text attributes that carry a dimension key are coalesced to 'unknown'.
# Ratings are 1-5 and nullable. average_rating is the mean of the categories
# actually scored. rating_band: unknown (no ratings), bad (<2), medium (<4),
# good (>=4).

-

airline_name_cleaned string

-

number_of_reviews int # all four subjects

first_review_date date # earliest date_submitted, any subject
latest_review_date date

-
aircraft_id PK string

aircraft_manufacturer string

-

cal_quarter_name string

fin_period int

fin_week int
fin_period_name string

fin_week_name string
